# Lab: design APIs end to end

Three checked labs bring the whole part together: each starts from requirements, asks you to design the endpoints,
measures a key decision in a simulation, and finishes on the simulator canvas or with the trade-offs that matter most.

| Lab | What you design | Checked steps |
|-----|-----------------|---------------|
| **[Product search](#/labs/api-product-search)** | Search, suggest and listing endpoints for a 20M-listing marketplace | API design, filter allowlists, deep paging, a cache that survives 30,000 searches/s |
| **[Video uploads](#/labs/api-video-uploads)** | Resumable upload sessions and processing status for 2 GB videos | API design, a flaky-network upload simulation, presigned URLs, a processing queue |
| **[Payments gateway](#/labs/api-payments-gateway)** | Payments as a state machine, refunds, webhooks, versioning | API design, the idempotency simulation, key reuse, async outcomes, account-pinned versions |

## Before you start

For each lab, write down on paper first, using the six steps from lesson 25.1:

1. Requirements with numbers.
2. Resources and their states.
3. Style and transport.
4. The endpoint table.
5. The cross-cutting checklist for each endpoint (auth, idempotency, limits, caching, pagination, events).
6. A latency budget and the top three failure modes.

Then run the lab and compare.

## Going further in the sandbox

The **API design** group in the [sandbox](#/sandbox) has ten starting points to explain and improve, each with a
problem to find: a public API with no limits, search on campaign day, file uploads, webhook delivery, payments, a
messenger, map tiles, a code judge during a contest, a price tracker and a game backend.

<details>
<summary>Self-review questions</summary>

- Which of your POST endpoints are unsafe to retry without an idempotency key?
- Which responses can be cached at a CDN, and which must never be?
- What happens to each design if its slowest dependency doubles its latency? If it's down for ten minutes?
- Which of your changes over the next year would be breaking, and how will you ship them anyway?
</details>
