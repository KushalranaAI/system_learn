# BGP and anycast

DNS tells you *which* IP to talk to. BGP decides *how packets get there*. It's the protocol the internet's tens of
thousands of independent networks use to tell each other which addresses they can reach. It runs on trust, it
converges in seconds to minutes, and one bad announcement can make a company vanish.

## Autonomous systems and prefixes

- An **autonomous system (AS)** is a network under one operator with its own routing policy, identified by a number:
  Facebook/Meta is AS32934, Cloudflare AS13335, Google AS15169.
- A **prefix** is a block of addresses, e.g. `157.240.0.0/16` (65,536 addresses) or `203.0.113.0/24` (256).
- ASes connect at exchange points and private links and run **eBGP** sessions with each other: customers, providers
  (transit) and peers.

## Announcements and withdrawals

An AS **announces** "I can reach this prefix", and each neighbour passes it on, prepending its own AS number:

```
AS64500 (origin) announces 203.0.113.0/24, AS_PATH = [64500]
   → AS3356 learns it, re-announces with AS_PATH = [3356 64500]
      → AS174 learns it, re-announces with AS_PATH = [174 3356 64500]
```

A router that hears the same prefix from several neighbours picks one best path. Simplified order:

1. Highest **local preference** (business policy: prefer customers over peers over transit)
2. Shortest **AS path**
3. Lowest origin type, lowest MED, eBGP over iBGP, lowest IGP cost to the next hop, then tie-breakers

Forwarding uses **longest prefix match**: if a router has both `208.65.152.0/22` and a more specific
`208.65.153.0/24`, packets for `208.65.153.x` follow the /24, whoever announced it.

A **withdrawal** says "I can no longer reach this prefix". Neighbours remove it and, if no other path exists, the
prefix disappears from the internet's routing tables within seconds to minutes.

## Anycast: one address, many places

With anycast, the **same prefix is announced from many locations**. Each user's packets follow BGP to the
topologically nearest one.

```
              203.0.113.0/24 announced from:
   Frankfurt PoP      Singapore PoP      Virginia PoP
        ▲                   ▲                  ▲
   user in Berlin    user in Jakarta    user in Boston
```

- **DNS**: the 13 root server names are served from well over a thousand anycast sites; managed DNS providers do the
  same, which is why a resolver usually reaches one in a few milliseconds.
- **CDNs and DDoS protection**: an attack is spread across every PoP instead of landing on one.
- **Failover**: if a PoP stops announcing, BGP moves its users to the next-nearest PoP, no DNS change needed.

Anycast works best for short exchanges (DNS over UDP, short HTTP requests). A routing change mid-connection can move
a TCP flow to a PoP that has never seen it, so long-lived connections need care or a unicast follow-up.

A common pattern: **health-checked announcements**. Each PoP's routers announce the anycast prefix only while local
services are healthy, so an unhealthy site removes itself automatically. This is exactly what bit Facebook.

## How one change took Facebook offline (October 4, 2021)

See [lesson 24.7](#/lesson/24.7) for the full postmortem. The mechanism:

```
1. During routine maintenance, a command meant to assess backbone capacity
   disconnected all of Facebook's backbone links between data centres.
   An audit tool that should have blocked it had a bug.

2. Facebook's edge DNS servers are designed to withdraw their BGP announcements
   when they can't reach the data centres (a healthy-check reflex, as above).
   Every DNS site saw the backbone gone, decided it was unhealthy, and withdrew.

3. The prefixes containing Facebook's authoritative DNS servers vanished from
   the internet. Resolvers everywhere got no answer for facebook.com,
   instagram.com, whatsapp.com. Retries multiplied resolver load worldwide.

4. Internal tools ran on the same network and names, so engineers had trouble
   reaching systems remotely and had to go on site to restore the backbone.
```

Facebook, Instagram and WhatsApp were unreachable for about six hours. Every individual piece worked as designed; the
outage came from a safety mechanism (withdraw when unhealthy) that, in a global failure, made *every* site unhealthy
at once. [Open it in the sandbox](#/sandbox?preset=out-facebook-bgp-2021).

## Route leaks and hijacks

BGP accepts announcements largely on trust:

- **Hijack, YouTube, February 2008**: Pakistan Telecom announced `208.65.153.0/24`, a more specific slice of
  YouTube's `/22`, intending to block YouTube domestically. Its upstream passed it on, longest-prefix match did the
  rest, and much of the world's YouTube traffic went to Pakistan for about two hours.
- **Leak, June 2019**: a small ISP using a BGP optimiser leaked thousands of more-specific routes to a customer, who
  leaked them to Verizon, who accepted and propagated them. Traffic for Cloudflare and others squeezed through a tiny
  network in Pennsylvania.

Defences:

| Defence | What it does |
|---------|--------------|
| Prefix filters on customer sessions | Accept only prefixes the customer is registered to announce |
| Max-prefix limits | Drop a session that suddenly sends far more routes than usual |
| **RPKI** route origin validation | Signed records saying which AS may originate a prefix and how specific; invalid routes are dropped |
| Monitoring (BGP looking glasses, alerts) | Notice within minutes when your prefixes are announced from elsewhere |

The command took down the backbone. Edge DNS servers, unable to reach the data centres, withdrew the BGP routes for
the prefixes they serve from. With no route to any authoritative DNS server, resolvers worldwide got timeouts or
SERVFAIL for every Facebook name, so even the parts of the network still running were unreachable by name. Internal
tooling depended on the same network, slowing recovery.

Design changes (any two): never let *every* anycast site withdraw at once (a site keeps announcing if it's the last
one, or withdrawal is capped at a fraction of sites); host authoritative DNS for critical names at least partly on
infrastructure that doesn't depend on your own backbone (or a second DNS provider); keep an out-of-band management
network and physical-access path that doesn't need production; make the audit tool fail closed and test it; stage
backbone commands to a small scope first.
</details>

## Key takeaways

- ASes announce prefixes; routers pick paths by policy and AS-path length; longest prefix match decides forwarding.
- Anycast announces one prefix from many sites so users reach the nearest; it's the backbone of DNS and CDNs.
- Withdrawing routes when unhealthy is a good local reflex that can become a global outage.
- BGP trusts announcements; prefix filters, RPKI and monitoring limit leaks and hijacks.
