# Gossip protocols

How do 1,000 nodes learn that node 417 died, or that a new node joined, without a central coordinator and without
every node pinging every other node? The same way rumours spread: **gossip**.

## The idea

Every second (one "round"), each node:
1. picks a few **random** peers (say 3);
2. exchanges its view of the cluster with them (members, their heartbeat counters, their state);
3. merges what it learns, keeping the newer information.

```
round 0:  1 node knows
round 1:  ~4 nodes know
round 2:  ~16
round 3:  ~64
…         the information reaches everyone in O(log N) rounds
```

For 1,000 nodes with a fan-out of 3, that's about **7–10 rounds**: under 10 seconds at one round per second, with
each node sending only 3 messages per round.

## What gets gossiped

- **Membership:** who's in the cluster, with a heartbeat counter each node increments for itself.
- **Failure suspicion:** if a node's heartbeat hasn't increased for a while, mark it *suspect*, then *dead*.
- **Metadata:** ring layout or token ownership (Cassandra), load and capacity, schema versions.

## Failure detection

A fixed timeout is fragile: networks jitter. The **phi-accrual detector** (Cassandra, Akka) tracks the distribution
of heartbeat inter-arrival times and outputs a *suspicion level* φ that rises as silence becomes statistically
unusual. You act when φ crosses a threshold (e.g. 8), which adapts automatically to slow or fast networks.

**SWIM** (used by Consul and memberlist) adds *indirect probes*: if A can't reach B, it asks C and D to try. That
separates "B is dead" from "the A–B link is flaky".

## Properties

| ✅ | ❌ |
|----|----|
| No single point of failure or bottleneck | Eventually consistent: nodes briefly disagree |
| Constant load per node regardless of cluster size | Propagation takes a few seconds |
| Tolerates message loss and node churn | Needs care to avoid gossiping stale data forever |

## Where it's used

Cassandra and ScyllaDB membership and ring state, Consul/Serf/memberlist (HashiCorp), Riak, Redis Cluster's bus,
Amazon's Dynamo, service meshes' health propagation, peer-to-peer systems and blockchains (transaction propagation).

## Try it

A 2,000-node cluster gossips every second with a fan-out of 3. Roughly how long until all nodes learn about a new
member? What's each node's message load?

<details>
<summary>Answer</summary>

Spread is about logarithmic: log₄(2000) ≈ 5.5, and with randomness and overlap, roughly **8–12 rounds**, so about
**10 seconds**. Each node sends just **3 messages per second**, independent of cluster size: that's gossip's main
appeal.
</details>

## Key takeaways

- Gossip spreads state by random peer exchanges; everyone knows within O(log N) rounds.
- The per-node load is constant, with no central coordinator.
- Phi-accrual detection adapts to network jitter; SWIM's indirect probes reduce false positives.
- It's eventually consistent membership: Cassandra, Consul, Redis Cluster and many more.
