# Merkle trees

Two replicas each hold 100 million keys. A few hundred differ. How do they find **which** ones without sending all
100M keys to each other? Compare **hashes of hashes**.

## The structure

Split the key space into ranges. Hash each range's contents (the leaves), then hash pairs of hashes upwards until one
**root hash** remains.

```
                    root = H(H12 + H34)
                  /                    \
          H12 = H(H1+H2)           H34 = H(H3+H4)
           /       \                /        \
     H1=H(range1) H2=H(range2) H3=H(range3) H4=H(range4)
```

## Comparing two replicas

```
1. Compare roots. Equal → the replicas are identical. Done (one hash exchanged!)
2. Different → compare the two children; descend only into subtrees whose hashes differ
3. At the leaves → exchange only the keys in the differing ranges
```

The work is proportional to the **number of differences × tree depth**, not to the data size. With 1M leaf ranges,
the depth is about 20.

## Where they're used

| System | Use |
|--------|-----|
| **Cassandra, Riak, DynamoDB-style stores** | Anti-entropy repair between replicas (lesson 13.5) |
| **Git** | Commits, trees and blobs are content-addressed hashes; comparing two repos is a tree walk |
| **Blockchains** | Prove a transaction is in a block with a short "Merkle proof" |
| **Certificate Transparency** | Tamper-evident append-only logs |
| **File sync / backup** (rsync-like, IPFS, ZFS) | Detect which blocks changed |
| **Databases' integrity checks** | Verify that data wasn't corrupted |

## Merkle proofs

To prove that item X belongs to a tree with a known root, send X plus the **sibling hashes** along its path (log₂ n of
them). The verifier recomputes up to the root and compares: about 20 hashes for a million items, instead of the whole
dataset.

## Maintaining the tree

- Recomputing everything on every write is expensive. Systems rebuild periodically (Cassandra builds trees during a
  repair), or update a leaf and its path incrementally (log n hashes per write).
- Ranges must be defined identically on both replicas, e.g. by token range (lesson 19.1).

## Try it

Two replicas with 16 leaf ranges differ in exactly one key. How many hash comparisons does the Merkle walk need,
versus comparing all leaf hashes directly?

<details>
<summary>Answer</summary>

The tree has depth 4 (16 = 2⁴). Compare the root (1), then 2 children at each of 4 levels (8) ≈ **9 comparisons** to
find the single differing leaf, then exchange only that range's keys. Comparing all 16 leaf hashes directly takes 16.
The gap grows hugely with more leaves (a million leaves: ~40 vs 1,000,000).
</details>

## Key takeaways

- A Merkle tree hashes data ranges and then hashes of hashes up to a root.
- Equal roots prove equality; differences are found by descending only into mismatched subtrees.
- It's used for replica repair, Git, blockchains, transparency logs and file sync.
- Merkle proofs verify membership with ~log₂ n hashes.
