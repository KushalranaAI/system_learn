# Cost engineering

For most web features, the marginal cost of one request is a fraction of a cent of CPU. For AI features it can be
cents to dollars, and it scales with **tokens**, not requests. A feature that looks cheap in a demo can cost more than
the rest of your infrastructure at scale. Cost is a design requirement, like latency.

## The cost equation

```
cost per task = Σ over model calls ( input_tokens × in_price
                                   − cached_tokens × cache_discount
                                   + output_tokens × out_price )
              + retrieval, guardrail and tool costs
cost per month = tasks per month × cost per task
```

Output tokens usually cost **3-5×** input tokens per token; bigger models cost **10-50×** smaller ones. So the levers
are, in rough order of impact: **which model**, **how many calls**, **how many tokens per call**, and **paying less per
token** (caching, batch).

## Worked baseline

A support bot: 1M conversations/month, 4 model calls each (agent steps), large model.

```
per call: 6,000 input (system 2,000 + tools 1,000 + docs 2,000 + history 1,000), 250 output
per conversation: 24,000 in, 1,000 out
at $3 / M in, $15 / M out: 24,000 × 3/1M + 1,000 × 15/1M = $0.072 + $0.015 = $0.087
per month: ≈ $87,000
```

## The levers

### 1. Routing and cascades

Most traffic is easy. Route by difficulty ([lesson 33.4](#/lesson/33.4)):

```
request ─► small model (cheap, fast) ─► confident & checks pass? ─yes─► answer   (~70-80% of traffic)
                                               │no
                                               └─► large model ─► answer
```

A router can be a classifier on the request, or a **cascade**: try small, escalate on low confidence or a failed
check. You pay for the small call on escalated requests too, so it wins only when most traffic stays small. Measure
quality per route with evals ([lesson 36.1](#/lesson/36.1)).

### 2. Caching

| Cache | What it saves | Notes |
|-------|---------------|-------|
| **Prompt (prefix) caching** | Re-reading a stable prefix (system prompt, tools, docs) | Anthropic bills cache reads at 10% of the input price; other providers discount cached input too. Put stable content first |
| **Exact response cache** | Whole call for identical requests | Works for FAQ-like traffic, templated features |
| **Semantic cache** | Whole call for *similar* requests | Risk of wrong answers; tune threshold ([lesson 33.5](#/lesson/33.5)) |

In the baseline, the first 3,000 tokens of every call (system + tools) are identical: caching them cuts input cost
on those tokens by 90%.

### 3. Fewer, shorter calls

- Merge agent steps with better tools ([lesson 35.8](#/lesson/35.8)); move fixed logic to code.
- Trim the system prompt (prompts grow by accretion; 2,000 tokens often compress to 800).
- Retrieve **fewer, better chunks** (rerank to top 3 instead of stuffing 10).
- Summarise history instead of resending it ([lesson 35.4](#/lesson/35.4)).
- Cap output: `max_tokens`, "answer in at most 3 sentences", structured output instead of prose.

### 4. Batch APIs

Work that doesn't need an answer now (nightly summaries, classification backfills, eval runs, embeddings) can go
through providers' batch APIs: results within 24 hours at about **50% off**. Architecturally it is a queue
([lesson 7.2](#/lesson/7.2)): submit a file of requests, poll for completion.

### 5. Self-hosting at high, steady volume

Past a utilisation threshold, running an open model on your own GPUs beats per-token prices ([lesson 33.7](#/lesson/33.7)).

## Guard the bill

- **Budgets per user and tenant** (tokens per minute and per day) stop abuse and runaway loops (OWASP LLM10).
- **Cost per feature dashboards** and alerts on $/hour ([lesson 36.2](#/lesson/36.2)).
- **Max steps and max tokens per task** for agents.
- Track **cost per successful task**, not per call: a cheap model that fails twice as often may cost more once you
  count retries and human escalations.

One plan (numbers are estimates you'd confirm with evals and billing data):

1. **Prompt caching** of the 3,000-token stable prefix: those tokens drop to 10% → input per call 6,000 → effectively

3. **Routing:** 75% of conversations handled by a small model ~10× cheaper; 25% stay large:
   0.75 × $0.0041 + 0.25 × $0.041 ≈ $0.013 (plus a cheap router call).
4. **Shorter output** (3-sentence answers, 250 → 150 tokens) trims a bit more.

Result ≈ $0.013-0.015 per conversation, about **$14,000/month: ~83% lower**. Keep the gates: resolution rate and
