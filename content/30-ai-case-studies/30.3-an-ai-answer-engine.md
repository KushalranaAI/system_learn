# An AI answer engine

An answer engine (Perplexity, ChatGPT search, Google's AI answers) takes a question, searches the web, reads the
best sources and writes an answer **with citations**. It is a web search engine ([lesson 22.2](#/lesson/22.2)) and a RAG system
(module 27) glued together, with tight latency targets and a hard correctness requirement: every claim should be
traceable to a source.

## The pipeline

```
question
  │ 1. query understanding / planning (small LLM): rewrite, split into sub-queries, pick freshness needs
  ▼
  2. retrieval: lexical (BM25) + semantic (vectors) over the index  ──►  hybrid candidate set (thousands)
  ▼
  3. ranking: cheap scorers ─► neural rerankers ─► cross-encoder on passages (top ~10-20 passages)
  ▼
  4. (optional) live fetch of top pages for freshness
  ▼
  5. generation (LLM): answer from the passages only, cite [1][2] per claim, stream to the user
  ▼
  6. citation check: each cited passage supports its sentence; drop or fix unsupported claims
```

## Query planning

"Is the new iPhone worth upgrading from a 13?" is several searches: the new model's specs, the 13's specs, reviews,
price. A planner step (a fast model) produces sub-queries and decides:
- **freshness** (news, prices, scores need recent pages; "what is TCP" doesn't);
- **vertical** (web, news, academic, shopping, code);
- **depth**: one round of search for simple facts; an agentic loop of search → read → search again for research
  questions ([lesson 27.7](#/lesson/27.7)). "Deep research" modes are this loop with a larger budget, minutes instead of seconds.

## Crawling and the index

You can't answer from pages you haven't indexed. Perplexity has described its own search infrastructure:
- an index tracking **over 200 billion unique URLs**, built by crawler and indexing fleets using tens of thousands
  of CPUs, handling **tens of thousands of indexing operations per second**;
- an **ML model decides which URLs to index and when to refresh them**, because re-crawling the whole web often is
  impossible; storage is tiered, with hot storage for authoritative domains and under-covered topics;
- the crawler respects `robots.txt`;
- documents are parsed and split into **self-contained sub-document spans**, so retrieval and ranking work on
  passages, not whole pages.

Perplexity also works with Vespa.ai, a serving engine that combines lexical and vector retrieval, filtering and
ranking models in one system.

## Ranking

Search ranking is a funnel, the same shape as recommendations ([lesson 30.5](#/lesson/30.5)):

| Stage | Candidates | Scorer | Cost per item |
|-------|-----------:|--------|---------------|
| Retrieval | millions → thousands | BM25 + ANN, filters (language, freshness, spam) | microseconds |
| First ranking | thousands → hundreds | Light model: lexical + embedding similarity + quality/authority signals | low |
| Rerank | hundreds → 10-20 passages | Cross-encoder reading query and passage together | high (GPU) |

Perplexity describes the same progression: hybrid retrieval tuned for recall, prefiltering of stale or
non-responsive content, then stages from fast lexical and embedding scorers to **cross-encoder rerankers**, scoring
both documents and sub-document spans.

## Citations

Citations are an architecture feature, not a prompt instruction:
1. Give each passage an id in the prompt (`[3] https://... "passage text"`).
2. Require the model to cite ids per sentence; constrain output format.
3. **Verify:** a fast check (or NLI/judge model) that the cited passage entails the sentence; remove claims that
   don't verify, or regenerate.
4. Render citations as links to the **exact passage**, so users can check.

The main failure is a **real citation for a claim the source doesn't make**. Groundedness evals ([lesson 27.6](#/lesson/27.6)) should
measure claim-level support, not just "has citations".

## Latency budget

```
planning           150 ms (small model)
retrieval          100-300 ms (parallel sub-queries)
rerank             100-200 ms (GPU cross-encoder, batched)
time to first token 300-500 ms (prefill of ~8-15k tokens of passages)
total to first word ≈ 1-1.5 s; then stream the answer, show sources first
```

Perplexity has published API latency for its search layer alone of about 358 ms p50 and 763 ms p95 (measured from
AWS us-east-1). Showing the source cards before the answer streams makes the wait feel shorter ([lesson 26.6](#/lesson/26.6)).

## Scale and cost

Perplexity reported about **200 million queries a day** on its search infrastructure. Per query: several retrievals,
a reranker pass over hundreds of passages, and an LLM call with 10k+ input tokens. Levers: cache answers to popular
and trending questions (with short TTLs), small models for planning and simple answers, prefix caching of the
system prompt, and routing deep-research mode to a separate, rate-limited pool.

## Risks

- **Prompt injection from web pages** ([lesson 29.4](#/lesson/29.4)): pages can hide instructions. Answer generation should have no
  tools that act; treat page text as data.
- **SEO spam and AI-generated junk** polluting the index: quality and authority signals in ranking.
- **Publisher relations and legal:** robots.txt compliance, attribution and traffic back to sources.

## Try it

Design an answer engine with citations for a news site's archive (20 years, 5M articles, updated every minute),
with answers in under 2 s to first token.

- **Ingestion:** CMS events → queue → parser → chunk into passages (paragraph groups with headline and date as
  metadata) → embed → upsert into a hybrid index (BM25 + vectors) within ~1 minute of publish.
- **Planner:** small model rewrites the question, extracts entities and date ranges ("in 2019", "latest") → filters.
- **Retrieve** top 500 hybrid candidates with date filters → light rerank to 100 → cross-encoder to 12 passages,
  with a recency boost for news-type queries.
- **Generate** with passage ids; require per-sentence citations; verify with an entailment check; show article
  cards first, then stream.
- **Budget:** planner 150 ms + retrieval 150 ms + rerank 150 ms + TTFT 500 ms ≈ 1 s.
- **Evals:** golden questions with known source articles: recall@12, citation precision, groundedness; a freshness
  test that asks about an article published 2 minutes ago.
