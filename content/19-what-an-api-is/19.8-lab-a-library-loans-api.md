# Lab: a library loans API

A city library wants one API for its app, its website and two partner schools. Members browse the catalogue, borrow
and return books; schools sync the whole catalogue every night over slow networks. Design the contract.

> **Interactive version:** [open the library loans lab](#/labs/api-library-loans) to design the endpoints, pick error
> codes and measure payload formats as checked steps.

## Step 1: Resources

What are the nouns?

<details>
<summary>Reference</summary>

`books` (the title), `copies` (a physical item, with a barcode and a branch), `members`, `loans` (a member borrowing a
copy, with a due date and a state), and later `holds` (a waitlist). Making **loan** a resource, not a verb, gives you
history, due dates and a place for "renew" and "return".
</details>

## Step 2: Endpoints

<details>
<summary>Reference</summary>

```
GET    /v1/books?q=&author=&cursor=        200  list (paginated)
GET    /v1/books/:id                       200  one book, with availability per branch
POST   /v1/loans          {copyId}         201  borrow  (Location: /v1/loans/:id)
GET    /v1/members/me/loans?status=active  200  my loans
POST   /v1/loans/:id/renew                 200  extend the due date
POST   /v1/loans/:id/return                200  end the loan (or PATCH {status: "returned"})
```
</details>

## Step 3: Errors

What do these return? (a) The last copy was lent a second ago. (b) A member asks for someone else's loans.
(c) A member with overdue fines tries to borrow. (d) `copyId` is missing.

<details>
<summary>Reference</summary>

(a) `409 Conflict`. (b) `403 Forbidden` (or `404` to avoid confirming the loan exists). (c) `409` or `422` with a
problem type like `/errors/fines-outstanding` and the amount, so the app can link to payment. (d) `400` (or `422`) with
the field name. All in RFC 9457 problem+json.
</details>

## Step 4: The nightly sync

Schools pull 200 records per page, 2,000 pages a second at peak, on 2 Mbps links. What would you change?

<details>
<summary>Reference</summary>

A cursor-paginated `GET /v1/books?updated_after=<timestamp>&cursor=` so schools sync **only changes** after the first
full load (this is the biggest win), plus `gzip`/Brotli. If the partners can handle it, offer a compact format
(Protobuf via `Accept: application/x-protobuf`) for the bulk endpoint, and keep JSON as the default.
</details>
